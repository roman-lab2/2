# AUTERA — рабочее демо автосервиса

Сайт автосервиса в Москве в светло-синей палитре: услуги, цены, контакты, запись без регистрации и закрытая админка. Next.js 16 / React 19, статическая публикация и Supabase Postgres + Auth.

## Запуск

Нужен Node.js 24 LTS.

```sh
npm ci
npm run dev
```

`lib/public-config.json` содержит URL демонстрационного Supabase и **публичный publishable key**. Это не секрет; доступ ограничен RLS, правами колонок и триггерами. Service-role ключи приложению не нужны и в код не добавляются. При переносе можно переопределить настройки через переменные из `.env.example`.

```sh
npm run typecheck
npm test
npm run build
```

Сборка создаёт `out/`, пригодный для статического хостинга. `.openai/hosting.json` связывает репозиторий с Sites.

## Страницы

- `/` — главная.
- `/services/`, `/prices/`, `/contacts/` — услуги, прайс, демонстрационные контакты.
- `/booking/?service=diagnostics` — запись с необязательным предварительным выбором услуги.
- `/admin/` — вход администратора и обработка записей.
- `/privacy/` — правила демонстрационной обработки данных.

Клиентские регистрация, вход и кабинет удалены. Существующие пользователи и старые таблицы базы не удалялись.

## Как работает запись

Один пост, часовые слоты 09:00–19:00 ежедневно. Бронирование доступно на 45 дней вперёд, не позднее чем за 30 минут до начала. Все даты и время вычисляются в `Europe/Moscow`, независимо от часового пояса устройства. Часовой слот резервирует приём и первичный осмотр; время ремонта согласовывается отдельно.

Клиент выбирает услугу, свободный слот, вводит имя, российский телефон, обязательную электронную почту и автомобиль. После сохранения получает номер и может скачать событие `.ics`. Занятость общая для всех услуг. Цена в демо — ориентир за работу, без запчастей.

`autera_book` — функция SECURITY INVOKER с INSERT без чтения клиентских записей. Приватный триггер атомарно резервирует слот; частичный уникальный индекс дополнительно исключает двойное бронирование. На один телефон разрешены максимум 3 будущие активные записи. Сбой проверки расписания не подменяется фиктивными свободными слотами.

## Администратор

Вход `/admin/` через существующий email и пароль Supabase Auth. Для выбранного владельца доступ уже выдан в подключённом демо. Пароли не менялись и в репозитории не сохраняются.

Права определяет отдельная таблица `autera_admins`, которую клиент не может изменять. Ни редактируемый профиль, ни user_metadata не дают админских прав. Для другого проекта назначение владельца выполняется доверенным SQL в Supabase Dashboard:

```sql
insert into public.autera_admins(user_id)
select id from auth.users where email = 'OWNER_EMAIL'
on conflict do nothing;
```

Администратор видит записи, фильтрует их по дате/статусу, ищет по имени/телефону/авто/номеру. Статусы: новая → подтверждена → выполнена; новую или подтверждённую можно отменить. Отмена освобождает время. Выполнить будущий приём нельзя. Время можно закрывать и открывать по часам или на весь день; забронированный слот защищён от изменения. Список обновляется каждые 30 секунд и вручную.

Старый RPC отмены клиентского кабинета закрыт; вызов старого auth-триггера через Data API также запрещён.

## База и проверки

SQL-миграции находятся в `supabase/migrations/`, уже применены к подключённому проекту. Они добавляют таблицы `autera_admins`, `autera_slots`, `autera_bookings` и не удаляют старые данные.

- `npm test` проверяет московские даты, границы дат и времени, нормализацию телефона.
- `tests/database.sql` проверяет гостевую запись, действия администратора, отмену, блокировку, повторное бронирование и изоляцию данных обычного пользователя. Запускается в SQL Editor; все тестовые изменения откатываются.
- Дополнительно выполнены два одновременных HTTP-запроса на один слот: один принят, второй получил `SLOT_UNAVAILABLE`. Анонимное чтение телефонов отклонено.
- Производственная сборка и TypeScript проходят.
- В среде выполнения отсутствует инструмент `cua_repl.js`, поэтому визуальная проверка в браузере не выполнена. Сервер предпросмотра в обход этого ограничения не запускался.

В существующих настройках проекта остаются предупреждения Supabase: `btree_gist` находится в `public`, а защита от скомпрометированных паролей отключена. Это настройки старой базы; новые таблицы защищены RLS.

## Мобильная версия

Упрощены тексты и главная страница: убраны декоративные подписи, нумерация и макет расписания. Актуальная палитра — светло-синяя: светлый фон, тёмный текст и голубые кнопки.

Для мобильных браузеров добавлены безопасные отступы экрана iPhone, `viewport-fit=cover`, размер ввода 16 px и области нажатия не меньше 44 px. Меню закрывается при выборе страницы, нажатии снаружи и Escape. Даты можно выбирать в системном календаре или прокручиваемой ленте дней. При переходе к следующему шагу форма прокручивается к заголовку. Скачивание календаря использует ссылку, добавленную в DOM, для совместимости с Safari.

Сборка и проверка типов проходят. Физические iPhone/Android и интерактивный WebKit в этой среде недоступны, проверка на реальных мобильных устройствах не выполнялась.

## Бесплатные письма о записи

Вместо SMS используются сервисные письма с отдельного Gmail через Google Apps Script. В форме обязательна электронная почта: поле проверяется и в браузере, и в базе. Для новых записей без email старый RPC возвращает `EMAIL_REQUIRED`; старые записи не удаляются и остаются с пустой почтой.

После решения администратора база создаёт одно событие в `autera_mail_queue`:

- `confirmed` — запись подтверждена; письмо содержит московскую дату, время и демонстрационный адрес.
- `declined` — новая запись отклонена до подтверждения.
- `cancelled` — ранее подтверждённая запись отменена.

Неотправленное подтверждение подавляется, если запись уже отменена. Тексты писем отмечают демонстрационный характер визита.

### Однократное подключение Gmail

1. Войдите в `/admin/`, откройте вкладку **«Почта»**.
2. Укажите отдельный адрес отправителя (для этого демо выбран `a64763774@gmail.com`) и нажмите **«Подготовить подключение Gmail»**.
3. Создайте проект [Google Apps Script](https://script.google.com/home/start) именно под выбранным аккаунтом. Вставьте подготовленный код в `Code.gs`, сохраните и выполните `installAuteraMail`, разрешив отправку писем.
4. Нажмите **«Проверить подключение»** в админке. Таймер Google затем проверяет очередь раз в минуту; иногда запуск задерживается на несколько минут.

Веб-приложение Google развёртывать не нужно. Скрипт перед каждым запуском сравнивает фактический Google-аккаунт с заданным отправителем. Аккаунт входа в админку не используется для отправки. Копируемый код доступен только администратору и содержит случайный ключ с правами только на обработку почтовой очереди; ключ хранится в базе только в виде SHA-256. Service-role ключ Supabase, пароль Gmail и доступ к чтению писем не нужны. Не публикуйте подготовленный код: он предназначен только для вашего проекта Google.

Обычный Gmail через Apps Script имеет [лимит 100 получателей в сутки](https://developers.google.com/apps-script/guides/services/quotas); квоты Google могут меняться. Скрипт проверяет оставшуюся квоту и не использует платные рассылки или купленный домен. Сообщения после исчерпания квоты остаются в очереди. Есть ограничение на число попыток. Остановить таймер можно функцией `stopAuteraMail`.

Состояние `sent` означает, что MailApp принял письмо; это не гарантия доставки во «Входящие». Неопределённый результат отмечается `uncertain` и не приводит к слепому повтору. Неподтверждённые сервером успешные отправки сохраняются в журнале Script Properties и сверяются при следующем запуске. Полную гарантию ровно одной доставки почтовая система не даёт.

Если Google ещё не подключён или таймер перестал работать, форма и админка прямо сообщают, что автоотправка недоступна. Подключение требует согласия владельца Google-аккаунта; без этого письма не отправляются.

### Проверки почтового механизма

`npm test` включает проверки почты, шаблонов, отказа при неверном аккаунте отправителя, квоты, восстановления подтверждения отправки и неопределённой ошибки. `tests/mail-database.sql` проверяет обязательность email, очередь статусов, подавление устаревшего подтверждения, изоляцию данных и права ограниченного почтового обработчика. Все SQL-фикстуры откатываются. Реальные письма в ходе разработки не отправлялись.

### Админка после переноса на домен

Адрес панели — `https://ваш-домен/admin/`. Пароль и права администратора хранятся в Supabase и не зависят от адреса сайта. При переносе обновите Site URL/разрешённые Redirect URLs в Supabase Auth, `metadataBase` в Next.js и ссылки в почтовом скрипте. Текущая страница входа использует email и пароль; публичной регистрации клиентов нет.
